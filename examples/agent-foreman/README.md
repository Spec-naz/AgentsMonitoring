# Small foreman monitor and durable coordinator relay — 0.1.0

AgentOps remains the only ticket authority. This package contains a read-only monitor, a durable relay to an existing native Codex coordinator thread, and optional bounded Hermes worker instructions. It is not another task manager or a general autonomous company. The runtime catalogue is private `~/.config/agent-foreman/catalogue.json`; source includes only `catalogue.example.json` with synthetic IDs. Root supplies the explicitly approved order/routes/dependencies and exact existing coordinator thread, never all arbitrary backlog items. Unknown tickets and user domains are not automatically eligible.

Run `python3 foreman.py`. The monitor opens SQLite with mode=ro, selects only workflow metadata and emits stable JSON. It never imports Ledger, writes state, mutates tasks, starts providers, schedules work or inputs terminal keystrokes. No clock, version, progress, titles, artifacts, diagnostics or contents appear. Relevant state-transition event sequence distinguishes a new return/rework loop; progress/cost/postcheck events are excluded. A changed actionable handoff/review/readiness state changes output; mere passage of time and version/progress updates do not. Errors produce a generic stable monitor_unavailable event. Missing DB is not created.

Any running/review ledger work owned by the routed worker suppresses prepared next work (also when that work is outside the catalogue). Pending review to the coordinator remains visible. One candidate per worker is selected in catalogue order, with already accepted queued work preferred. Review handoff does not block independent next work. Dependencies only release after done, not merely offered/cancelled. Blocked/cancelled/done are not dispatch candidates. A global `~/.local/state/agent-foreman/PAUSED` marker suppresses all events, even if the DB is unavailable. This marker is a local operational control, not authentication; the same Unix owner can alter code and files.

## Functional native coordinator wake

`python3 relay.py poll --thread EXISTING_THREAD_UUID` performs at most one native `codex queue --thread … --message … --resume` operation per invocation. The message includes a deterministic FOREMAN RECEIPT ID and approved event metadata. This is the installed CLI's supported daemon queue/resume path, not TUI keystrokes. It does not choose a provider/model or call an inference API; resuming the existing thread may consume its already approved subscription. The CLI explicitly warns that a failed resume can still exit zero. Accordingly, successful queueing is always `queued_resume_unverified`, never an invented turn ACK.

The relay holds a nonblocking flock on an append-opened lock (never truncating it), stores and fsyncs a private reservation before invoking queue, checks PAUSED again, and saves only disposition metadata. It never persists CLI stdout/stderr. Identical event/thread fingerprints are not queued again. New actual state transitions get new fingerprints. A timeout, warning at exit zero, process error or crash after reservation stays unverified/reserved and is not automatically replayed. If a pause arrives after reservation but before queue, that event stays paused_before_enqueue for explicit reconciliation; removing PAUSED does not silently retry it.

`python3 relay.py status` reads private receipts. After observing real native processing or the appropriate actual task transition, the coordinator can run `python3 relay.py ack --event FULL_RECEIPT_HASH --evidence 'specific observed native turn or task transition'`. Only a known exact receipt and nonempty bounded evidence are accepted. This is an explicit operational declaration by the observer, not cryptographic verification or proof that the work is done. Ack never retries a message or mutates AgentOps. An unverified event must be reconciled and handled manually by the coordinator, not automatically reset or sent again.

Root can install a source wrapper for `relay.py poll` in Hermes' existing script directory and schedule a short **no_agent** pilot roughly every five minutes. Thus routine polls do not invoke a Hermes LLM; only a genuinely new event queues/resumes the existing coordinator. No job is created/enabled/run by this patch. Before claiming production functionality root must independently review source/tests, verify the exact thread and financial scope, create the actual scheduler registration, observe its first queued event, and store an actual coordinator ACK. No hard token/runtime cap is implemented here. Optional future judgment-based Hermes runs could instead use the existing monitor_script hash gate and WORKER.md, but that is separate from this mechanical relay.

## Boundary still missing

The relay wakes only the existing Codex coordinator. It cannot prove Claude TUI idleness, deliver safely to every provider, authenticate an actor, or atomically cancel a queue operation when the user types a native stop. WORKER.md therefore requires an existing supported transport, fresh actual task read, pause recheck, idempotency and actual accept/start ACK before assigning/waking a downstream worker. Without such a transport downstream work is delivery_pending; a local log or TEAM delivery alone is not successful execution. The relay adds durable per-event reservations and explicit receipts but no global CAS/pause/delivery transaction. It never impersonates Kodak for AgentOps offer/accept/done and does not review or deploy another agent's work.

Stable output, transition fingerprints and reservations are not exactly-once remote messaging. State loss/manual reset can permit duplicates, and queueing may succeed just before an exception. Preserve the receipt ledger and reconcile ambiguous effects. Readiness/review ownership are factual declarations, not process health. Current worker state may change immediately after the read; the coordinator must refresh before acting. Individual paused tasks must be represented by an existing blocked/cancelled/waiting state; this schema adds no second per-task pause store. Failed queues do not trigger an automatic paid fallback. A scheduled relay should be disabled or globally PAUSED if the user stops autonomous coordination, even though ordinary native messages remain available.

Tests use synthetic temporary SQLite and mocked queue processes only: `python3 -m unittest discover -s tests -v`. No real queue, production schedules, model calls, credentials, messages, task changes or restarts are part of these tests. New catalogue entries require explicit coordinator approval and validation; merely appearing in backlog is insufficient.
